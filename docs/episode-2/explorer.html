The data has no name for the play, so the tool measures only a written definition. Here you write it: who carried, how many yards to go, the formation, and the downs. Each combination is a different dictionary entry, and the page shows what the tool printed for it: the definition, every filter with the plays left after it, and how often the defined play converted against every other short-yardage rush.     Not in this output: whether the play should be legal. A gap is how often each kind of play converted in the plays kept. It does not say why, and it does not say what the rule should be.

    A downs choice here is part of the definition, so it narrows only the defined play. The comparison stays every other rush with the same yards to go, on any down. The tool's --downs flag, which the agent can add to a command, narrows both groups instead.

    About these answers

    Nothing here is computed in your browser. A script, build-explorer-data.mjs, wrote each of the 54 definitions these buttons can build as an entry in a scratch dictionary, asked the tool to measure each one for seven sets of seasons, 378 answers in all, saved what it printed, and removed the scratch dictionary. The page divides the counts the tool printed and rounds once, the same way the tool does.

    Only the reference definition has a dictionary entry of its own: tush-push, which the agent writes on air on October 26, 2026, and which goes into the repo afterward. The other 53 were written to the scratch dictionary only. Every command on this page names the scratch entry, as the script ran it, so against the repo's dictionary the tool refuses it: no entry of that name is on file. For the reference definition, use --play tush-push once the episode's entry is in the repo. To measure any other, write it as an entry first.
