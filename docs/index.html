The Monday Morning Agent

An agent that checks the tape. A football argument goes in. A ruling comes out, with every filter it applied on screen. Here is how it is set up, for someone who has never built one.

Everybody knows the Monday morning quarterback, the person who second-guesses every coaching decision after the fact. This is one that goes back and counts. It is the short version of episode 1 of an eight-episode O'Reilly live series. It skips the code and keeps the shape: what already existed, what had to be written, and what one run looks like. Every number on this page is real.

In one minute. You hand the agent a claim, such as "you have to establish the run." It turns the claim into a question, asks one small tool to count plays under filters it chooses, and writes a short ruling: the answer from five complete NFL seasons, the answer from this season, and how far apart they are. The tool prints every filter it applied, so you can check the agent's work. The one thing written for this is a policy, a job description the agent follows. A run takes about fifteen seconds. You can change the filters yourself without installing anything.

The argument, and why one number is not enough

"You have to establish the run" is the oldest argument in football. Here is the check: take every team in every game, work out what share of its plays were runs, sort them into four equal groups, and ask how often each group won. Five seasons, 2021 through 2025.

Whole game77.7%vs19.2%The teams that ran most against the teams that ran least. It looks like proof.
First half only53.0%vs46.1%"Establish" means early. Early, the gap nearly disappears.
Second half only87.0%vs11.7%Teams that are ahead run to use the clock. Winners run late.

Same plays, same tool. One filter changed the story. An agent that reported only the first number would have been confident, well formatted, and wrong. That is why every filter has to be visible, to the person and to the agent. Try the three filters yourself.

What already existed

None of this was made by the agent, and most of it was not made for the agent.

Data

Public play-by-play

Every NFL play, published by the nflverse community under a CC BY 4.0 license: 372 columns per play, refreshed during the season.

The cut

18 of 372 columns

A small script keeps only the columns the question needs. The betting-line columns are not among them, so the agent cannot read one even by mistake.

The tool

One read-only script

query-plays.mjs counts under the filters it is given and prints every filter in order. A third of a second. It changes nothing.

Runtime

Claude Code CLI

One command reads a prompt, calls only the tools it is allowed to call, and exits. There is no server to write.

How it fits together

Two halves. The grey half is deterministic: counting plays has one right answer, so a small tool does it the same way every time. The amber half is judgment: a written policy that says how to turn a claim into a question and what the agent may and may not say. Keeping the halves apart is the whole design.

What one run looks like

  1. The claim goes in as one sentence, the way a fan would say it.
  2. The agent restates it as a question. "Establish" means early, so it decides to compare the first half with the second half. Nobody told it that in the prompt. The policy did.
  3. Four tool calls. First half and second half for five seasons, then the same two for this season. Each call's filters appear on screen as it lands.
  4. It compares the two answers and says whether the difference is more than a few weeks of games can support.
  5. One ruling, under 250 words, ending with the commands it ran so anyone can rerun them.
  6. The runner saves the ruling to a file. The agent itself cannot write anything.

The claim: If establishing the run matters, teams that run on a larger share of first-half plays should win clearly more often, and that gap should not be dwarfed by the second-half gap.

Five seasons: First half: ran most 53.0%, ran least 46.1%, gap 6.9 points. Second half: ran most 87.0%, ran least 11.7%, gap 75.4 points. 710 team-games per group.

This season: First half: 58.3% against 37.5%, gap 20.8 points. Second half: 91.7% against 20.8%. With 24 team-games per group, a single game moves a win rate by 4.2 points.

Ruling: Does not hold as stated, because the first-half association is small while the second-half one is enormous, which leans toward teams that are ahead running to use the clock, not early running producing wins.

What these plays cannot tell you: Whether running causes winning or winning causes running, since the tool measures only an association.

node ./query-plays.mjs --seasons 2021-2025 --half 1
node ./query-plays.mjs --seasons 2021-2025 --half 2
node ./query-plays.mjs --seasons 2026 --half 1
node ./query-plays.mjs --seasons 2026 --half 2

The policy, in eight sections

The policy is a Markdown file of about 700 words, written like a job description. Its headings run in the order the agent has to work: who it is, how it looks, how it asks, what it shows, what it may not say, and last, what it may run.

Job descriptionNot a pundit, no opinions about teams. The person in the room who went back and counted.
Your one toolThe command and its filters. The filter list it prints is the truth about what was measured. Never open the data file directly.
Turn the claim into a questionSay what would have to be true, including when in the game. Then run the comparison that could prove the claim wrong.
Answer it twiceFive complete seasons, then this season, with the same filters. Repeat any small-sample warning.
Show every filterEach number comes with its filters. End with the exact commands. Never report a number the tool did not print.
What you may not sayNo predictions, no advice to bettors or fantasy players, no claim that running causes winning, and no betting lines.
The output contractOne ruling, under 250 words, in the same seven parts every time.
Tools you may useOne script. No writing, no network. If the tool fails, say so; never invent a number to cover it.

What carries to your own agent

Give the agent one door to the data

It does not write queries. It picks filters for one fixed tool. So you check the filters it chose, not code it wrote.

Make the tool show its work

Every filter, in order, with the count left after each. A flag the agent forgot is a filter it did not apply, and the printout shows it.

Scope the data, not only the instructions

The policy says never use betting lines. The file has none. The second one is the guarantee.

Ask for the comparison that could prove it wrong

The whole-game number agrees with the claim. The first-half number tests it. The policy asks for the test.

Keep the allowlist exact

One script by name. Not "any Node command," which would allow arbitrary code. Asked to open the data file directly, the agent declined.

The numbers are fixed; the sentence is not

Across identical runs the numbers never changed, but the one-line ruling came back as "does not hold as stated" and as "holds only weakly." Read the numbers.

Try it yourself

With no install at all: the explorer page shows the tool's real output for every combination of its buttons.

To run the agent, you need a Mac or Linux machine with Node, git, and the Claude Code CLI signed in. The data is already in the repo.

# get the kit
git clone https://github.com/ismayc/monday-morning-agent.git
cd monday-morning-agent/episode-1

# the tool on its own: whole game, then first half
node ./query-plays.mjs --seasons 2021-2025
node ./query-plays.mjs --seasons 2021-2025 --half 1

# the whole agent, with any claim about running the ball
./run-analyst.sh "You have to establish the run."
